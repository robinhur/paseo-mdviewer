# 아키텍처

MDViewer는 Paseo 안에서 Markdown 파일을 열고, 읽기 좋게 그리고, 같은 탭에서 고칠 수 있게 하는 플러그인이다. 데몬이 Markdown을 HTML로 바꾸고, 앱은 격리된 iframe에 그 HTML을 보여 주며 다이어그램은 그 안에서 그린다.

English: [docs/ARCHITECTURE.md](../ARCHITECTURE.md)

## 목표와 비목표

목표

- Paseo 안에서 `.md` 파일을 클릭 한 번으로 연다. 답변 링크, 파일 트리, 검색, 답변 아래 버튼이 모두 같은 뷰어로 이어진다.
- GitHub 수준의 Markdown과 Mermaid 다이어그램, 수식을 데스크톱에서 보기 좋게 그린다.
- 보기·분할·원문 모드로 같은 탭에서 편집하고 저장한다.
- 에이전트가 쓴 문서를 놓치지 않게 한다.
- 모든 문서를 신뢰하지 않는 내용으로 다룬다.

비목표

- 대화 답변을 그리지 않는다. 답변은 Paseo나 다른 플러그인이 그린다.
- 코드 에디터가 아니다. 원문 편집은 일반 텍스트 입력이다.
- PDF나 Office 같은 다른 문서 형식은 다루지 않는다.

## 구조

| 위치 | 실행 환경 | 하는 일 |
|---|---|---|
| `engine/render.ts` | 빌드할 때 번들 | markdown-it과 플러그인, highlight.js, KaTeX로 Markdown을 HTML로 변환 |
| `server/` | 데몬 하위 프로세스 | RPC 처리, Markdown 파일 접근, 파일 관리자, 답변 버튼, 에이전트 도구 |
| `server/generated/` | 빌드 산출물 | `engine.js`(렌더러 번들)와 `runtime.ts`(Mermaid, DOMPurify, KaTeX 스타일과 글꼴) |
| `client/` | Paseo 앱 | 파일 패널, 파일별 탭, 툴바, 경로 메뉴, 설정 화면, 대화 행, 번역 |
| `client/shell.ts` | iframe 안 | 스타일, 소독, Mermaid, 목차, 찾기, 확대, 링크·복사·체크박스 처리 |
| `shared/` | 양쪽 | RPC 계약, 설정 스키마, 경로 찾기, 텍스트 편집 |
| `scripts/` | 개발 머신 | 렌더러 번들, 런타임 내장, 서드파티 고지 생성(`build.mjs`), 스크린샷(`screenshots.mts`) |

데몬은 플러그인의 서버 코드를 자체 번들러로 묶고, 가져온 패키지의 타입 선언까지 따라간다. markdown-it과 highlight.js의 타입 선언은 따라갈 수 없어서, `scripts/build.mjs`가 렌더러를 미리 `server/generated/engine.js`로 묶는다. 같은 이유로 Mermaid, DOMPurify, KaTeX도 실행 중에 `node_modules`에서 읽지 않고 생성 모듈에 문자열로 넣는다. 그래서 플러그인에는 실행 의존성이 없다.

## 주요 흐름

### 파일 열기

1. 사용자가 답변 링크, 파일 트리, 검색 결과에서 `.md` 파일을 연다.
2. Paseo가 파일 탭을 만들고, 그 확장자에 기억된 뷰어인 MDViewer로 연다.
3. 두 종류 패널은 `useMarkdownFile`로 데몬에서 파일을 읽고 외부 변경을 따라간다.
4. 렌더 RPC가 HTML을 돌려주면 패널이 `postMessage`로 iframe에 넘긴다.

답변 버튼, `/mdv`, 문서 안 링크, 에이전트 카드는 파일별 탭을 연다. 파일마다 `doc-<경로 해시>` ID의 에이전트 패널이 있어서, 같은 대화에서 같은 파일을 열면 그 탭으로 이동한다. 에이전트 패널을 쓰는 이유는 Paseo가 워크스페이스 패널을 전부 새 탭 메뉴에 올리기 때문이다. 워크스페이스 패널로 등록하면 연 파일마다 메뉴 항목이 하나씩 생긴다. 데몬은 연 파일 목록을 `plugin-data/paseo-mdviewer/recent.json`에 두고, 클라이언트가 시작할 때 그 패널들을 등록한다. 그래서 Paseo가 복원한 탭이 자기 패널을 찾는다.

Paseo 파일 탭에는 자기 대화가 없다. 그 안에서 다른 Markdown 파일로 가는 링크를 누르면, 워크스페이스에서 가장 최근에 갱신된 대화 옆에 연다.

### 그리기

- 데몬: front matter를 떼어 내고, markdown-it으로 렌더하고, 블록마다 `data-line`을 붙이고, 로컬 이미지는 data URI로 넣고, 로컬 링크에는 `data-path`를 붙인다.
- iframe: HTML을 소독해 넣은 뒤 Mermaid 블록을 하나씩 SVG로 바꾼다. 다이어그램 색은 Mermaid의 `base` 테마와 테마 변수를 써서 Paseo 테마에서 가져온다. 바뀌지 않은 다이어그램은 캐시한 SVG를 재사용해서 편집 중 깜빡임을 줄인다.

### 편집과 저장

- 분할이나 원문 모드에서 입력하면 초안이 생기고, 0.14초 뒤에 다시 그린다.
- 자동 저장이 켜져 있으면 입력을 멈추고 0.7초 뒤에 저장한다. 미저장 초안에는 저장 버튼도 나온다. 저장 도중 입력한 내용은 다음 저장까지 보존한다.
- 두 종류 탭은 같은 버전 검사 RPC로 저장한다. 초안은 첫 편집 시점의 내용 버전을 유지하며, 주기적 조회로 기준을 바꾸지 않는다. 외부 변경이 있으면 자동 저장을 멈추고 명시적으로 버리거나 덮어쓸 때까지 초안을 보존한다. 파일이 삭제되거나 읽기에 실패해도 미저장 원문에 접근할 수 있다.
- 데몬은 실제 경로별로 저장을 순차 실행하고 내용 버전을 검사한다. 원본 옆 임시 파일을 완성한 뒤 다시 검사하고 교체한다. Markdown 심볼릭 링크, 파일 권한, UTF-8 BOM을 보존하며, 없는 파일과 Markdown이 아닌 대상은 거절한다.
- 다른 프로그램은 이 프로세스 내부 큐를 공유하지 않는다. 마지막 검사와 교체 사이의 외부 쓰기까지 OS 수준의 원자적 비교·교체로 보호하지는 않는다.

### 변경 문서 버튼

1. `agent.turn.before` 훅이 에이전트 작업 폴더 아래 일반 Markdown 파일의 경로와 메타데이터를 범위 제한 스냅샷으로 남긴다. 숨김 항목, 의존성과 빌드 폴더, 심볼릭 링크는 건너뛴다. 파일 본문은 읽지 않는다.
2. 같은 턴의 `agent.turn.after` 훅이 설정 조회나 스캔을 기다리기 전에 종료 관측 시각을 남기고, 새 스냅샷을 시작 스냅샷과 비교한다. 새로 생겼거나 메타데이터가 바뀌었으며 파일시스템 변경 시각이 종료 관측 시각보다 늦지 않은 파일만 후보로 삼는다(밀리초 해상도). 답변 글과 Markdown 서식은 판단에 쓰지 않는다.
3. 최근 변경 순서로 최대 12개를 `source: "turn-changes"`가 있는 `mdviewer-files` 행으로 붙이고, "이번 턴에 변경된 문서" 제목을 표시한다. 이전의 언급 기반 행은 파싱은 되지만 숨기며, 저장된 타임라인 항목은 삭제하지 않는다.
4. 변경이 없거나 맞는 시작 스냅샷이 없으면 행을 만들지 않는다. 끝까지 확인한 폴더는 바로 아래 항목 이름을 기록한다. 다른 하위 경로가 스캔 제한에 걸려도 완료된 부모·상위 폴더의 기록으로 문서나 그 문서를 담은 폴더가 새로 생겼는지 판정한다. 원래 있었지만 스캔하지 못한 경로는 새 파일로 추정하지 않는다.

턴 시작 알림은 비동기이며 에이전트 실행 전에 완료를 보장하는 장벽이 아니다. 아주 빠른 변경이 스캔보다 앞설 수 있고, 스캔 범위 밖의 파일을 놓칠 수 있다. 같은 폴더의 다른 프로그램이나 에이전트가 변경한 파일도 포함된다. 작성자나 중요도를 판정하는 기능이 아니라 파일 변경 신호다. 기존 파일 링크, 파일 패널, `/mdv`의 열기 동작은 유지한다.

## 보안

Markdown 파일에는 HTML이 들어갈 수 있고, 사용자가 쓰지 않은 저장소에서 온 파일일 수도 있다.

- iframe은 `sandbox="allow-scripts"`로 만든다. 출처가 분리되어 앱에 접근할 수 없다.
- 미리보기 문서에 콘텐츠 보안 정책을 건다. 스크립트는 문서의 nonce가 있어야 하고, 스타일은 인라인을 허용하고, 이미지는 `data:`와 `https:`, 글꼴은 `data:`만 허용한다. `connect-src`를 포함한 나머지는 모두 `'none'`이다.
- 렌더한 HTML은 넣기 전에 DOMPurify로 소독한다. `style`, `form`, `iframe`, `object`, `embed`, `base`, `link`, `meta`도 제거한다.
- Mermaid는 `securityLevel: "strict"`로 돌린다.
- 뷰어 자체 요소의 ID는 `mdv-`로 시작한다. 그래서 제목 ID가 뷰어 스타일을 가로챌 수 없다.
- 패널이 iframe에서 받는 메시지는 `ready`, `open`, `external`, `copy`, `toggleTask`, `scale`이다. `external`은 `http`, `https`, `mailto` 링크만 연다. `open`은 Markdown 파일이면 MDViewer로 열고, 그 밖의 로컬 파일은 파일 관리자에서 보여 준다.
- 데몬의 읽기, 상태 확인, 쓰기, 기억 처리는 Markdown 파일이 아닌 경로를 거절한다. 쓰기는 파일을 새로 만들지 않는다. 파일 관리자의 "열기" 동작은 Markdown 파일에만 동작한다.

`test/browser.test.mts`가 실제 미리보기 문서에 악의적인 문서를 띄워서 이 성질들을 확인한다.

## 불변 조건

- iframe 밖의 앱 코드는 DOM을 건드리지 않는다. DOM 접근은 `client/web.ts`에만 있고 웹 플랫폼에서만 돈다.
- 웹 뷰가 없는 플랫폼에서는 Paseo 기본 Markdown 컴포넌트로 문서를 보여 준다.
- 타임라인 행의 종류 이름은 소문자, 숫자, 하이픈만 쓴다.
- 앱의 글자 색은 모두 Paseo 테마에서 가져오고, 화면 글자는 모두 `client/locales/`에서 가져온다.
- 서버 응답은 문장이 아니라 코드를 담는다. 번역은 클라이언트가 한다.

## 실패 처리

| 상황 | 동작 |
|---|---|
| 렌더 RPC 실패 | 이전 렌더 결과를 유지한다 |
| 소독기를 불러오지 못함 | 문서를 보여 주지 않고 이유를 알린다 |
| Mermaid 문법 오류 | 그 블록 자리에 오류를 보여 주고 나머지는 그린다 |
| 파일 삭제 | 탭에 "파일을 찾을 수 없습니다"를 보여 준다 |
| 저장 충돌 | 배너로 버릴지 덮어쓸지 묻는다 |
| 패널이 그리다가 오류를 냄 | 탭에 오류를 보여 주고 플러그인 로그에 남긴다 |
| 턴 훅 실패 | 버튼 행을 붙이지 않고 오류를 플러그인 로그에 남긴다 |

## 알려진 한계

- Paseo 파일 탭의 아이콘은 Paseo가 파일 종류에 따라 정한다. 플러그인은 바꿀 수 없다.
- 답변을 그리는 쪽이 그 링크를 어떻게 열지 정한다. Better Paseo의 "Plugin markdown for replies"가 켜져 있으면 링크가 운영체제로 열린다.
- Paseo 0.16.2의 플러그인 타임라인 행에는 호스트의 파일 링크 처리 문맥이 전달되지 않는다. 공개 `Markdown` 컴포넌트로 파일 링크를 그려도 해당 탭을 열 수 없다. SDK 0.15.4에도 기본 파일 탭 열기 API가 없어 답변 버튼은 파일별 플러그인 패널을 유지한다. 근거는 [호스트 타임라인 경계](https://github.com/getpaseo/paseo/blob/2ee30f4164af42ba209236ab3a31bf9532592fc3/packages/app/src/agent-stream/view.tsx#L945-L948)다.
- 파일별 탭은 그 탭을 연 대화에 속한다.
- 파일 관리자 동작은 데몬이 도는 기기에서 실행된다.
